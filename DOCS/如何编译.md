# 如何在 Xcode 里编译这个工程

> `.xcodeproj` **不在仓库里**，直接用 Xcode 打开项目文件夹会什么都看不到。
> 必须先用 XcodeGen 从 `project.yml` 生成一次。

## 0. 确认 Xcode 能用

刚装完 Xcode，第一次必须手动跑起来一次，让它装完附加组件、签掉许可协议：

```bash
sudo xcode-select -s /Applications/Xcode.app/Contents/Developer
sudo xcodebuild -license accept
xcodebuild -version          # 应输出 Xcode 16.x 或更高
```

`xcode-select` 那一步是必要的：装了 Xcode 但命令行仍指向 Command Line Tools 是常见状态，
表现为 `xcodebuild` 报 "requires Xcode"。

## 1. 装 XcodeGen

```bash
brew install xcodegen
```

没有 Homebrew 的话，去 [XcodeGen Releases](https://github.com/yonaskolb/XcodeGen/releases)
下 `xcodegen.zip`，解压后：

```bash
cd xcodegen && ./install.sh
```

## 2. 拿到代码

```bash
git clone https://github.com/ViteZhang/CountdownPro.git
cd CountdownPro
git checkout claude/swiftui-countdown-app-v1-vdcxpk
```

## 3. 生成工程并打开

```bash
xcodegen generate
open CountdownPro.xcodeproj
```

**只要改了 `project.yml`、或者新增/删除了源文件，就要重跑一次 `xcodegen generate`。**
工程文件是产物，`project.yml` 才是真相源。生成出来的 `.xcodeproj` 已被 gitignore 忽略。

## 4. 选模拟器，不要选真机

Xcode 左上角的运行目标选任意 **iPhone 模拟器**（iOS 17 及以上）。

第一次编译请务必用模拟器，原因是 **App Groups**：

App 与小组件靠 App Group 共享 SwiftData 存储文件。真机安装要求这个 group
在你的开发者账号下真实注册过，免费 Apple ID **做不到**，会卡在签名报错上——
那是账号配置问题，不是代码问题，会白白浪费你排查编译错误的时间。

模拟器不校验 entitlement，`containerURL(forSecurityApplicationGroupIdentifier:)`
照常返回可用路径，小组件也能正常读到数据。

> 之后要上真机：付费开发者账号 → Certificates, Identifiers & Profiles
> 里注册 `group.com.countdownpro.shared` → 在 Xcode 两个 target 的
> Signing & Capabilities 里各选一次 Team。
> **两个 target 的 App Group 必须完全一致**，不一致的表现是小组件永远显示占位态。

## 5. 编译

- `⌘B` 编译
- `⌘R` 运行
- `⌘U` 跑测试（scheme 里已挂上 `CountdownKitTests` 与 `DesignTokensTests`，共 221 个）

## 6. 把编译错误捞出来

Xcode 的错误面板不方便复制。用命令行跑一遍，输出可直接粘贴：

```bash
xcodebuild -project CountdownPro.xcodeproj \
           -scheme CountdownPro \
           -destination 'generic/platform=iOS Simulator' \
           -configuration Debug build 2>&1 \
  | grep -E "error:|warning:" | sort -u
```

用 `generic/platform=iOS Simulator` 而不是写死某个机型名，
免得因为本机没装那台模拟器而报 destination 找不到。

## 预期会遇到什么

**视图层从未被编译过。** `CountdownKit` 与 `DesignTokens` 是纯 Foundation，
在 Linux 上跑过 221 个测试；但 `CountdownStore`（SwiftData）、`CountdownUI`（SwiftUI）、
App target、Widget Extension 全部被条件编译跳过了。**首次编译报错是预期内的。**

工程开着 Swift 6 语言模式 + `SWIFT_STRICT_CONCURRENCY: complete`，
并发相关的问题会是**硬错误**而不是警告。如果首轮错误里大半是
`Sendable` / actor 隔离之类，可以先在 `project.yml` 里临时把
`SWIFT_VERSION` 改成 `"5.0"`，重新生成，把真正的编译错误先分离出来修完，
再切回 6.0 收并发。

另外两件已知的、不影响编译的事：

- 没有 App Icon 与启动图资源，Xcode 会给警告，不影响运行。
- 界面上会看到大量 `⟪待补文案：…⟫`。**这是设计如此**，不是 bug——
  资料没给的文案一律显式占位，禁止自拟填充。清单见 `DOCS/待补文案清单.md`。
